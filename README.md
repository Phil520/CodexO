# CodexO

<img src="https://raw.githubusercontent.com/bean/CodexO/main/docs/screenshot.png" width="720" alt="CodexO 菜单栏图标七档月相">

macOS 菜单栏小工具，实时显示 Codex 的**剩余额度**。

菜单栏上是一颗**双层圆标**：

- **外圈**——5 小时窗口的剩余进度环，绿 / 橙 / 红随余量变色
- **内圈**——每周窗口的**月相**，七档：月亮越圆，余量越多

从左到右是「**数字 + 图标**」，数字即 5 小时窗口的剩余百分比。

![七档月相](docs/moon-phases.png)

点开菜单可以看到两个窗口的剩余 / 已用、重置倒计时，以及**这份读数是什么时候的**。

---

## 特点

- **只读，不联网**——只读本机 `~/.codex/sessions` 里的会话日志，不上传任何数据，不发任何网络请求
- **原生**——Swift + AppKit，`swiftc` 直接编译，没有 Xcode 工程，没有第三方依赖
- **常驻稳定**——空载约 12 MB 内存，长期运行无泄漏（有 4000 次压测与加速实跑数据，见下方）
- **一枝配色通吃**——月相靠**形状**而非透明度表达，深浅两种菜单栏下都清晰
- **能看见数据的年龄**——菜单里直接显示读数时间与「多少分钟前」，不会把陈旧数据伪装成实时

## 安装

1. 从 [Releases](https://github.com/bean/CodexO/releases) 下载 `CodexO-1.0.0.zip`
2. 解压得到 `CodexO.app`
3. 拖进「应用程序」文件夹
4. 双击启动（不显示 Dock 图标，只在菜单栏）

> **首次启动可能被 Gatekeeper 拦一下。** 因为没有 Apple 开发者证书做公证，
> 右键点 `CodexO.app` → **打开** → 再点「打开」即可。
> 这是一次性的，之后正常双击就行。

### 前置条件

- macOS 13 或更高
- 机器上装好并且**实际用过** Codex（需要 `~/.codex/sessions` 里有会话日志）
- **若菜单栏看不见图标：先退出 Hidden Bar。** 本机实测只要 Hidden Bar 在跑，
  任何新建的菜单栏项都会被 macOS 排到屏幕外（x ≈ -4100）。这与 CodexO 无关，
  一个 10 行的最小程序同样会被挤出去。Bartender / Ice / Dozer 同理。

## 自行编译

```bash
git clone https://github.com/bean/CodexO.git
cd CodexO
bash build.sh
open output/CodexO.app
```

只需要 Xcode 命令行工具，无其他依赖。

## 它显示的数字是什么意思

两个窗口，都是**剩余**（不是已用）：

| 窗口 | 长度 | 对应 |
|------|------|------|
| 5 小时窗口 | 300 分钟 | 菜单栏数字 + 外圈进度环 |
| 每周窗口 | 10080 分钟 | 内圈月相 |

数据来源是 Codex 每次发请求时由服务端下发的额度快照，写进会话日志的
`token_count` 事件里。取数时**跨文件按事件时间戳取真正最新的那条**，
而不是按文件修改时间。

## ⚠️ 一个必须说清楚的限制

**CodexO 显示的是「最近一次 Codex 请求时」的读数，不是实时读数。**

Codex 官方 App 是自己直接查服务端的，而 CodexO 读的是本地日志里最近一次落盘的快照。
两者对照：

- **你持续在用 Codex 时**——每个请求都会刷新日志，两边基本一致
- **你停手之后**——官方 App 继续跟着服务端走，CodexO 冻在最后一次的值上

所以「数字不动」通常不是坏了，而是**这段时间没有新的请求**。
菜单里那行「读数 14:32（38 分钟前）」就是给这件事看的——它直接告诉你这份数据有多旧。

想消除这个落差就得接官方实时接口（`account/rateLimits/read`），
但那需要常驻一个子进程并处理认证续期，v1.0 没做。

## 菜单项

立即刷新 / 打开 Codex 会话目录 / 开机自动启动（开关）/ 写入诊断日志 / 退出

## 资源占用

| 路径 | 4000 次后的净变化 |
|------|------------------|
| 定时刷新 | +0.02 MB |
| 强制重画图标 | ±0 B |
| 打开菜单 | ±0 B |

真实进程加速跑：0.02 秒/次连跑 3 分钟（≈ 正常运行 6.25 天），内存从 15.4 MB
落到 12.9 MB 后**一直平在 12.9 MB**，全程无上升趋势。

## 项目结构

| 目录 | 用途 |
|------|------|
| `src/` | 源代码 |
| `tests/` | 回归测试 + 月相几何的像素级验证 |
| `tools/` | 预览图生成器（把图标画成 PNG 目视核对） |
| `docs/` | 设计说明、取数口径、开发笔记 |
| `build.sh` | 一键编译打包 |

其中两处值得一看：

- **`docs/开发笔记.md`**——完整记录了几个代价不小的坑：为什么必须按事件时间戳取数、
  为什么尾部读取必须在字节层面切行、以及内存泄漏是怎么定位和复现的
- **`docs/设计说明.md`**——月相的画法、七档的划分依据

## 诊断日志

`~/Library/Logs/CodexUsageMenuBar.log`，超过 512 KB 自动滚动一份。
菜单里可手动触发写入。「写了多少、写了什么」有完整记录，包括**实际写到菜单栏按钮上的那串字**——
这是为了能区分「算错了」和「算对了但没推到界面上」，两者在屏幕上的表现完全一样。
